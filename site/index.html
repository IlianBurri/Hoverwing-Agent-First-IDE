Open-source desktop IDE · Windows, macOS, Linux

Let coding agents write code without letting them run your machine.

Kestrel runs the agent you already use – Claude Code, Gemini CLI or any ACP agent – and holds every file it writes until you have read the diff. Commands, websites and secret files need your yes first.

How an agent's change reaches your code

  1. A checkpoint is saved

    Before every agent turn Kestrel snapshots the project in a separate Git directory. Your own .git is never touched.

  2. The agent asks before it acts

    Running a command, opening a web page or calling a tool shows a request with the exact command line. Allow it once, always for this project, or deny it.

  3. You review the diff

    Edits are held back. Accept a whole file or only the sections you want; Kestrel refuses to overwrite a file that changed in the meantime.

  4. Undo is one click away

    Restore any checkpoint. Kestrel saves the current state first, so nothing is lost.

Use the AI you already have

Kestrel does not sell or route AI usage. You connect what you have, and API keys stay in your system keychain.

What you can connect
You have In Kestrel it becomes
Claude Code, Gemini CLI or another ACP agent An agent in the side panel. You sign in inside the agent; Kestrel never sees those credentials.
An OpenRouter or OpenAI-compatible API key A provider for the built-in chat and inline completion, with automatic fallback to your next model on rate limits.
A GPU or a fast CPU Local models through Ollama or llama.cpp. The setup assistant checks your hardware, recommends models and installs Ollama from its official release.
MCP servers Tools your agent can call through Kestrel, each with its own allow, ask or deny setting.

A complete editor around it

Monaco editor with language servers for TypeScript, Python, Rust and Go: completion, go to definition and a problems list. A Git panel to stage, commit, switch branches, pull and push. Terminals, project search, a Docker panel and a browser your agent can inspect.

Projects you open for the first time start in restricted mode: language servers and Git only run code from a project after you trust it.

Arrange it the way you work

Put any command in the toolbar, move the sidebar and agent panel to either side, hide what you do not use and save the result as a layout.

Or describe it: “agent on the left, Git on the right, no terminal”. Your chat model proposes a layout, Kestrel lists every change in plain words, and nothing moves until you press Apply. Undo restores the previous layout.

What Kestrel will not do without you

Run commands or open websites for an agent
Every risky action goes through one permission system. Rules live in the app data folder, where agents cannot edit them, and every decision is logged.
Show secrets to an agent or a model
.env files, keys and SSH folders are never read for agents or sent to models. API keys are stored in the system keychain.
Give an agent your whole machine
An agent can run in a Docker container that only sees the project folder, with secret files blanked out.
Collect data about you
No telemetry, no analytics, no account.

All releases and notes · Code signing policy · App privacy

Code signing policy

Free code signing provided by SignPath.io, certificate by SignPath Foundation. The application is in progress; until it is approved, Windows installers are unsigned. Only binaries built by GitHub Actions from the public repository are signed, and every release is approved by hand. Roles and details are in the README.

Privacy of the app: this program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Two exceptions can be turned off: the update check on start (GitHub) and the first download of the TypeScript language server (npm). See the app privacy statement.
