How an agent’s change reaches your code

Hoverwing runs the agent you already use: Claude Code, Gemini CLI or any ACP agent.

  1. The agent shows its plan

    Every task starts with a plan you can read, and the agent ticks off each step as it works.

  2. A checkpoint is saved

    Before every agent turn Hoverwing snapshots the project in a separate Git directory. Your own .git is never touched.

  3. The agent asks before it acts

    Running a command, opening a web page or calling a tool shows a request with the exact command line. Allow it once, always for this project, or deny it.

  4. You review the diff

    Edits are held back. Accept a whole file or only the sections you want; Hoverwing refuses to overwrite a file that changed in the meantime.

  5. Undo is one click away

    Restore any checkpoint. Hoverwing saves the current state first, so nothing is lost.

  6. You see where it runs

    The status bar says whether the agent runs directly on your system or in a Docker sandbox, so you never have to guess.

Use the AI you already have

Hoverwing does not sell or route AI usage. You connect what you have, and API keys stay in your system keychain.

What you can connect
You have In Hoverwing it becomes
Claude Code, Gemini CLI or another ACP agent An agent in the side panel, up to four side by side in tabs. Pick model, effort and mode per tab and see how full its context is. You sign in inside the agent; Hoverwing never sees those credentials.
An OpenRouter or OpenAI-compatible API key A provider for the built-in chat and inline completion, with automatic fallback to your next model on rate limits.
A GPU or a fast CPU Local models through Ollama or llama.cpp. The setup assistant checks your hardware, recommends models and installs Ollama from its official release.
MCP servers Tools your agent can call through Hoverwing, each with its own allow, ask or deny setting.

A complete editor around it

Monaco editor with language servers for TypeScript, Python, Rust and Go: completion, go to definition and a problems list. A Git panel to stage, commit, switch branches, pull and push. Sign in with GitHub to clone your repositories in two clicks. Terminals, project search, a Docker panel and a browser your agent can inspect.

Restricted until you trust it

Projects you open for the first time start in restricted mode: language servers and Git only run code from a project after you trust it.

Arrange it the way you work

Put any command in the toolbar, move the sidebar and agent panel to either side, hide what you do not use and save the result as a layout.

Or describe it: “agent on the left, Git on the right, no terminal”. Your chat model proposes a layout, Hoverwing lists every change in plain words, and nothing moves until you press Apply. Undo restores the previous layout.

What Hoverwing will not do without you

Run commands or open websites for an agent
Every risky action goes through one permission system. Rules live in the app data folder, where agents cannot edit them, and every decision is logged.
Show secrets to an agent or a model
.env files, keys and SSH folders are never read for agents or sent to models. API keys are stored in the system keychain.
Give an agent your whole machine
An agent can run in a Docker container that only sees the project folder, with secret files blanked out.
Collect data about you
No telemetry, no analytics, no account.

Code signing policy

Windows installers are not code-signed yet, so SmartScreen shows “unknown publisher” on the first start (More info, then Run anyway). Once releases are signed, only binaries built by GitHub Actions from the public repository will be signed, and every release will be approved by hand. Roles and details are in the README.

Privacy of the app: this program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Two exceptions can be turned off: the update check on start (GitHub) and the first download of the TypeScript language server (npm). Signing in to GitHub contacts GitHub only when you ask for it. See the app privacy statement.
